# Commit

변경사항을 분석해 프로젝트 컨벤션에 맞는 커밋을 준비하고, 사용자의 명시적 승인 후에만 커밋한다.

## 트리거

다음 요청에 사용한다.

- 커밋
- 커밋해줘
- 변경사항 저장
- 변경사항을 커밋해 달라는 의미의 유사한 요청

## 절차

1. `git status --short`와 `git diff`를 실행해 작업 트리의 변경사항을 확인한다. 스테이징된 변경사항이 있으면 `git diff --cached`도 확인한다.
2. 변경 파일과 diff 내용을 기능·목적별 논리적 단위로 분류한다. 서로 무관한 변경은 하나의 커밋에 섞지 않는다.
3. 프로젝트의 기존 커밋 로그와 설정에서 별도 컨벤션을 확인한다. 별도 규칙이 없으면 다음 형식을 사용한다.

   `type: 한국어 요약`

   허용하는 기본 type은 `feat`, `fix`, `refactor`, `chore`이며, 변경 목적에 가장 적합한 하나를 선택한다. 요약은 간결한 한국어 명령형 또는 서술형으로 작성한다.
4. 커밋하기 전에 다음 내용을 사용자에게 제시하고 승인을 요청한다.

   - 커밋별 포함 파일 또는 변경 범위
   - 제안 커밋 메시지
   - 분리한 이유(둘 이상의 커밋인 경우)

5. 사용자가 승인한 커밋만 생성한다. 승인 전에는 `git add`, `git commit` 등 작업 트리를 변경하는 명령을 실행하지 않는다.
6. 승인 범위가 불명확하거나 일부 커밋만 승인된 경우 승인된 범위만 처리하고 나머지는 보류한다. 커밋 후에는 생성된 커밋과 남은 변경사항을 확인해 보고한다.

## 안전 규칙

- 변경 내용을 확인하지 않고 커밋하지 않는다.
- 사용자의 승인 없이 자동으로 커밋하지 않는다.
- 기존의 사용자 변경사항을 되돌리거나 삭제하지 않는다.
- 커밋 훅 실패, 충돌, 또는 저장소 상태 이상이 발생하면 원인을 보고하고 재시도 여부를 묻는다.
- 변경사항이 없으면 커밋하지 않고 상태를 알려준다.
